## Reliable update installation

### Fixed

- Fixed an update failure reporting `Could not verify the application being updated: Access is denied. (os error 5)`. The helper now waits for the previous process to finish exiting when Windows cannot return its image path, then verifies the installed executable's checksum before replacement.
- A running process still blocks replacement, a queryable process must match the target executable, and the existing timeout, backup, and checksum checks remain in place.

### Validation

The native update regression reproduced the original failure using a real Windows process handle that permits waiting but denies image-path queries. Both this case and the normal query case passed after the fix, including executable replacement, backup verification, restart, and isolated cleanup. Formatting, Clippy, and 26 automated tests passed.

Download **MultiMonitorBrightness-v0.2.4.exe** for Windows 10/11 x64, or retry **Settings → Updates → Download and install** from v0.2.1 or newer. The downloaded executable also provides the update helper, so the fix applies during that upgrade. If the failed update closed the app, reopen your existing executable and check for updates again. Existing settings and user data are preserved. Version 0.2.0 still requires a one-time manual upgrade because it expects the old asset name.
